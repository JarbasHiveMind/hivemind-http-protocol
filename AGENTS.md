# AGENTS.md — `hivemind-http-protocol`

Guidance for AI coding agents (and humans) working in this repository. Read it
fully before making changes. It encodes conventions that are not obvious from the
code and that, if ignored, produce work that will be rejected.

## Repo

REST/HTTP transport plugin for
[HiveMind-core](https://github.com/JarbasHiveMind/HiveMind-core): an
alternative to the default WebSocket transport, using HTTP polling (POST to
send, GET to receive) instead of a persistent connection, for environments
where long-lived TCP is not possible (firewalls, IoT gateways, HTTP-only
proxies). It is loaded by hivemind-core at runtime via the
`hivemind.network.protocol` entry point (`hivemind-http-plugin` →
`HiveMindHttpProtocol`) and can run alongside the WebSocket transport. Part of
the [HiveMind](https://github.com/JarbasHiveMind) ecosystem — a protocol for
connecting satellite devices to a hub running
[OpenVoiceOS](https://github.com/OpenVoiceOS). Related repos:
[hivemind-plugin-manager](https://github.com/JarbasHiveMind/hivemind-plugin-manager)
(defines the `NetworkProtocolFactory` interface this repo implements),
[hivemind-bus-client](https://github.com/JarbasHiveMind/hivemind-bus-client)
(the reference client, including `HiveMindHTTPClient`), and the WebSocket
transport this one mirrors ACL/auth semantics against.

## Layout / build / test

- Package module: `hivemind_http_protocol/` (single-file `__init__.py` plus
  `version.py`). Tests live in `tests/` (unit-style files plus `tests/e2e/`,
  which is gated behind `hivescope` — `conftest.py` only loads the hivescope
  pytest plugin when it is importable). Do not create a second test
  directory.
- Set up a throwaway environment inside your clone; never touch a shared venv:
  `python3 -m venv .venv && VIRTUAL_ENV=$PWD/.venv uv pip install -e ".[test]" --prerelease=allow`
- Run the suite in the foreground: `python3 -m pytest tests -q`.
- `uv`, never `pip`. If latest prereleases fail to install or resolve, that is
  a bug to FIX at the source, not to work around with a pin downgrade.

## Tests

- Adversarial by default. A regression test must **fail before the fix and pass
  after** — prove it by reverting only the source (`git apply -R`, never
  `git stash` across worktrees) and watching the test flip.
- Tests must be mutation-proof: gutting the feature must fail the test. A test
  that only asserts a mock was called, without asserting the real behaviour, is
  weak — note it.
- Never skip a test because an optional dependency is missing.
- CI green is permission to review, not to merge. A non-trivial change gets an
  adversarial review before it lands.

## Repo-specific rules

- Wire back-compat is law: deployed HTTP clients (including
  `HiveMindHTTPClient` from `hivemind-bus-client`) must keep working across
  versions of this plugin. Do not change endpoint paths, parameter names, or
  response shapes (`/connect`, `/disconnect`, `/send_message`,
  `/get_messages`, `/get_binary_messages`) without a compatibility path for
  older clients.
- ACL/auth field parity with the WebSocket transport is a standing
  requirement, not a suggestion: every field copied from the client-DB row
  onto the connection object over WebSocket (`can_broadcast`,
  `intent_blacklist`, `skill_blacklist`, `can_propagate`, `can_escalate`,
  `is_admin`, `allowed_types`) must be copied here too — see the handshake
  code in `hivemind_http_protocol/__init__.py` (`get_client` /
  `ConnectHandler`) and `tests/test_acl_parity.py`. A field present on one
  transport and silently ignored on the other is a security-relevant bug: two
  transports into one node must reach the same admission decision for the
  same database row.
- A key that fails validation must be rejected fast
  (`handle_invalid_key_connected`), not left to time out or retry silently.
- Never add a new HiveMind bus message type from this repo; this plugin only
  transports existing `HiveMessage`/`HiveMessageType` traffic over HTTP.
- This is a text/JSON + base64-binary transport, not the audio-binary path;
  it has no homelab-only restriction of its own, but any audio/binary payload
  it relays is still subject to the ecosystem's homelab-only-by-design rule
  for real audio streaming.
